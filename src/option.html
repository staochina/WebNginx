Server Rules

规则按 server 分组；每个表格一行对应一个 location。页面上的编辑需点击 Save and Sync 后才会真正生效。

1. 何时生效
  • 设置页内的新增、修改、删除、Active、拖动排序、Import 都只改编辑区；必须点 Save and Sync 才会写入并应用到浏览器。
  • 未保存就关闭设置页，上述改动会丢失。
  • Debug Log 开关立即切换，与规则保存无关；不写入 storage，关闭设置页或 Service Worker 重启后恢复为关闭。
  • 弹窗 Enable Active Rules 是全局总开关，会立刻启用/清空已保存的规则；与单条 Active 是两层控制。
  • Rule Preview 在 Save and Sync 成功后刷新。
2. 填写语法

Location（匹配路径）

  • / — 前缀匹配该域名下所有路径
  • /api — 前缀匹配 /api 开头的路径
  • ~ ^https://example\\.com/(.*)$ — 区分大小写的正则
  • ~* \\.png$ — 不区分大小写的正则

Directives（每行一条，以 ; 结尾）

  • proxy_pass https://目标; — 子资源 / XHR URL 重定向（保留路径；自动跳过 OPTIONS 并补 CORS）
  • rewrite 正则 替换 last; — 正则改写（可用 break / last / redirect）
  • proxy_set_header 名称 值; — 修改请求头
  • add_header 名称 值; — 追加响应头
  • return 403; / return 444; — 拦截请求
3. 规则优先级
  • 不是 nginx 原生择优（无 exact / ^~ / 最长前缀优先）。
  • 同一 server 内多条同时命中时：表格更下面的 Location 优先（可用 ⋮⋮ 拖动；需 Save and Sync 后生效）。
  • 建议把更具体的路径放在下面；Inactive 不参与竞争。
  • 一条 Location 同时含重定向/拦截与改 Header 时，可能生成多条浏览器规则，最终按 declarativeNetRequest 规则裁决。
4. 导入 / 导出
  • Export：下载当前编辑区为 nginx 风格 .conf（含 Active/Inactive；Inactive 写作 inactive on;）。会带上页面上尚未 Save 的修改。
  • Import：从 .conf / .txt 载入并整体替换编辑区（不合并）；有内容时会确认。
  • 导入只更新预览，须再点 Save and Sync 才真正生效。
  • 导入会校验语法；不支持的指令会失败。推荐使用本扩展导出的文件。
  • 若只想备份已生效规则：先 Save and Sync，再 Export。
5. 跨域（能力与限制）
  • 本扩展做浏览器侧 URL 重定向 / 改头，不是真正的 nginx 反向代理。
  • proxy_pass 会自动：① 不重定向 OPTIONS（避免 preflight 被跳转报错）；② 给目标响应补上 CORS 头（可用 add_header 覆盖）。
  • Location 与 proxy_pass 路径一致时会保留完整请求路径（例如 /svr/otb/cube/... → 目标同路径），不会截成固定前缀。
  • 浏览器仍会做 CORS 校验；带 Cookie 的请求可能需把 Access-Control-Allow-Origin 写成具体 Origin。
6. 调试日志
  • 工具栏 Debug Log 左右开关会立即切换（无需 Save and Sync）。开启后才会在控制台打印 [WebNginx] 日志。
  • 每次切换开关都会清空控制台：设置页控制台与 Service Worker 控制台各清除一次。
  • 查看后台日志：打开 chrome://extensions → 本扩展 →「Service Worker」/「检查视图」。
  • 规则命中日志（onRuleMatchedDebug）通常仅在未打包的扩展上可用；正式商店安装版可能看不到命中明细。
7. 配置示例

跨站重定向：server_name = www.abcd.com，Location = /，Directives = proxy_pass http://127.0.0.1:8080; （会自动处理 OPTIONS / CORS；Save and Sync 后生效）

改完后点击 Save and Sync。
